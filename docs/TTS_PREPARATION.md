# Offline příprava textů pro další commandery

Leonidas, Scipio Africanus, Spartacus, Germanicus a Zhuge Liang mají v `data/commanders/<id>/tts-plan/` české textové návrhy pro bezpečná commander-specific Media ID. Vstupem je nezávisle ověřená `research/voice-lines.csv`; do plánu nesmí proniknout culture, unit ani global shared hlas. `voice-lines-cz.csv` obsahuje jeden řádek pro každý bezpečný Media ID, `tts-plan.csv` jeden řádek pro každý odlišný plánovaný hlasový výkon. Obojí jsou textová metadata, nikoli pokyn k automatické placené generaci.

České návrhy Leonidase a Scipia jsou v `data/commanders/shared-research/commander-translation-memory.tsv`. Spartacus, Germanicus a Zhuge Liang mají vlastní `data/commanders/<id>/tts-plan/translation-memory.tsv`, protože stejná anglická fráze („Cut them down!“) má u vzbouřeného gladiátora a u římského velitele znít jinak. Soubor pokrývá jen anglické fráze použité v bezpečné sadě daného běhu. Generátor odmítne chybějící i nadbytečnou položku. Při změně anglického přepisu je nutné opravit překlad a znovu vytvořit plány:

```powershell
python -B -m tools.tts.research_plan --commander leonidas --commander scipio-africanus --translation-memory data/commanders/shared-research/commander-translation-memory.tsv
python -B -m tools.mod --commander leonidas validate
python -B -m tools.mod --commander scipio-africanus validate
python -B -m tools.validation.repository
```

`PREPARED` označuje český návrh nad angličtinou s úrovní CONFIRMED/HIGH; nejde o tvrzení, že člověk nahrávku poslechl nebo schválil herecký projev. `PROVISIONAL_ENGLISH` má český pracovní návrh, ale původní anglické slovo čeká na ověření. `NEEDS_MANUAL_TRANSCRIPTION` nemá použitelný anglický text ani český návrh. Finální rozhodnutí o přepisu se zapisují jako oprava v `transcript-corrections.json` s explicitním `resolution`. `HUMAN_CONFIRMED` (vždy s CONFIRMED) je text převzatý doslova od majitele projektu. `SECOND_OPINION_RESOLVED` (vždy s HIGH) je výsledek nezávislé druhé analýzy. Tyto štítky se propisují do `transcript_resolution` i do `transcript-review-decisions.csv`. Surové ASR hypotézy zůstávají ve sloupcích `raw_transcript` a `stt_*`. Požadované WAVy zůstávají mimo repository v soukromém `commander-research`; cesty jsou uvedeny v `research/manual-transcript-review.md` a `tts-plan/transcript-review-decisions.csv`.

Jeden budoucí výkon může pokrýt více Media IDs jen při shodném dekódovaném PCM, formátu, anglickém znění a českém návrhu. Jeden originální výkon může být ve Wwise použit jako emote i povel; plán sjednotí styl/model/tags pro celou takovou skupinu. Rozdílné WEM bajty nejsou překážkou pro společnou budoucí nahrávku, ale každé ID bude potřebovat samostatný přesně velký WEM a vlastní kontrolu. Skupiny nikdy nesdílejí výkon mezi dvěma novými commandery.

Routing podle ověřeného historického projektu: `eleven_v4` je výchozí. `eleven_v3` je návrh jen pro označený battlecry/warcry nebo krátký výrazný výkřik v příslušné schopnosti. Jde o doporučení, ne o ověření aktuální dostupnosti API. Tags mají jednu či dvě vlastnosti.

Spartacus a Germanicus mají v `tools/tts/research_plan.py` explicitní voice profile a širší kontextová pravidla převzatá z runtime-ověřeného Hannibala (42/305 na v3): battlecry, charge a další agresivní unit orders, urgentní/rozzlobené announcer výkřiky (útok na základnu či jednotku, friendly fire, docházející čas, routing). Standardní povely zůstávají na v4. Volitelné sloupce `delivery_style`, `recommended_model`, `recommended_tags` v commander translation memory zaznamenávají revidované rozhodnutí pro konkrétní frázi a mají přednost před pravidlem. Validace vynucuje: v3 ⇔ tag `shouting` ⇔ expresivní styl (`BATTLE_SHOUT`, `URGENT_SHOUT`, `ANGRY_SHOUT`, …), nejvýše dvě vlastnosti. Leonidas a Scipio bez profilu zachovávají publikované routování bajtově shodně.

```powershell
python -B -m tools.tts.research_plan --commander spartacus --translation-memory data/commanders/spartacus/tts-plan/translation-memory.tsv --archive-root $archiveRoot
python -B -m tools.tts.research_plan --commander germanicus --translation-memory data/commanders/germanicus/tts-plan/translation-memory.tsv --archive-root $archiveRoot
python -B -m tools.tts.research_plan --commander zhuge-liang --translation-memory data/commanders/zhuge-liang/tts-plan/translation-memory.tsv --archive-root $archiveRoot
```

Zhuge Liang má klidný profil stratéga s příznakem `shout_needs_audio_evidence`. Kontextová v3 pravidla (charge a další agresivní povely, battlecry, urgentní/rozzlobený announcer) u něj platí jen tehdy, když originál prokazatelně křičí. Důkazem je, že některá lokální Whisper hypotéza je celá velkými písmeny; stejný princip projekt už používá u `.isupper()` pro schopnosti Leonidase a Scipia. Jinak řádek zůstává na v4 s `[urgent, commanding]`. Profily bez příznaku se nemění: plány Leonidase, Scipia, Spartaca i Germanica se z nové verze generují bajtově shodně. Tagy `strategic` a `composed` jsou v projektu nové, dosud nebyly ověřené runtime poslechem. Ověří je až pilot (frontend citáty) před dalšími požadavky.

`--archive-root` navíc zapíše soukromou kopii `commander-research/<id>/manual-transcript-review-local.md` s absolutními cestami k WAV mimo repozitář; veřejná verze v `research/` obsahuje jen cesty relativní k archivu. `manual-transcript-review.md` vzniká vždy, i když žádná položka nezbývá. `pilot-menu.csv` a `pilot-battle.csv` v research i tts-plan nyní obsahují angličtinu, češtinu, styl, model a tags; vybírají jen bezpečné texty s CONFIRMED/HIGH přepisem a doloženým triggerem.

`wem_budget_risk` je orientační triáž podle původních bajtů, trvání a délky české věty; přesné prahy jsou v `translation-review.md`. Není to úspěch ani neúspěch reálného kódování. Pro pozdější WEM se nesmí oříznout řeč, zkrátit čas strečinkem ani změnit originální velikost entry. Připravené plány nevytvářejí release manifest a nic nezapisují do hry.

## Produkční TTS po schváleném pilotu

U Spartaca se po pilotním poslechu změnilo lidské rozhodnutí o routingu: výchozí je `eleven_v3`; `eleven_v4` patří hlavně silným bojovým pokřikům a urgentním hlasitým povelům. „Tasit čepele!“ má výslovně `eleven_v3`. Původní `recommended_model` v offline CSV zůstává historickým návrhem; produkce čte samostatný finální `final-routing.csv`, aby nepřepisovala kanonické texty. Před placeným během musí routing pokrýt všechny skupiny, ověřit všechny členy proti nezávislé bezpečné inventuře a spočítat konzervativní kreditní odhad.

`tools.tts.production` přijímá `--commander`, `--voice-name`, `--routing`, `--output` a případně `--pilot-journal`, `--decoder-path`. Ukládá každý dokončený request, hash MP3 a účetní údaj do `generation-state.json`; při obnovení znovu neposílá již dokončené ani nejasně odeslané requesty. Pilotní MP3 znovu použije jen při shodě hlasu, modelu, textu, tagů a hashe. MP3 validuje přímým dekódem přes lokálně získanou knihovnu `miniaudio` v ignorovaném `work/`. Jediný technický retry je dostupný přes `--retry-empty-history MEDIA_ID HISTORY_ITEM_ID` až po ověření nulového audia v historii ElevenLabs; stav trvale zablokuje další opakování. Skutečný placený běh vyžaduje výslovné zadání a nikdy nevytváří WEM, PACK ani instalaci hry.

Další volby: `--voice-id` musí souhlasit s výsledkem vyhledání `--voice-name` (jinak hard stop). `--require-model` vynutí jeden model pro celý routing. `--max-credits` je strop konzervativní projekce 1 credit/znak pro zbývající requesty a zároveň průběžná pojistka; nedostatek kreditů zastaví běh před prvním requestem. `--preflight-only` provede jen read-only kontrolu hlasu, modelu, kreditů a importu pilotu. Comparison pilot journal s více hlasy je podporovaný: použijí se jen požadavky s přesně shodným voice ID/name, ostatní hlasy se nikdy neimportují. `--auto-retry-technical` je výslovně povolený nejvýše jeden automatický retry na výkon po jasné technické chybě (síť, HTTP 429/5xx, prázdná či poškozená odpověď). Po transport/5xx chybě klient nejprve hledá request v ElevenLabs history a již naúčtované audio jen stáhne; nový placený request pošle, jen když history nic neobsahuje. HTTP 401/402/403/404 a quota/voice odmítnutí jsou hard stop celého běhu. `--audit` znovu dekóduje všechny MP3, kontroluje clipping a provenance a páruje každé request ID s history; zapíše `audio-audit.json` a `history-audit.json` a hlásí i položky history bez záznamu v ledgeru (možné duplicitní platby).

U Zhuge Lianga uživatel po pilotu finálně zvolil hlas `ZhugeLiang_CZ_v2` a `eleven_v4` pro všech 292 výkonů; `recommended_model` v plánu zůstává historickým metadatem a `final-routing.csv` v ignorovaném `work/tts-production/zhuge-liang/` má všude `eleven_v4`. Čtyři pilotní výstupy tohoto hlasu se znovu použily, 288 výkonů se vygenerovalo nově.

`tools.tts.regenerate` je cílená obdoba produkčního klienta pro výslovně schválený seznam Media IDs. Delivery CSV (`media_id,attempt,tags`) určuje jen tagy daného pokusu; text se vždy bere z canonical `tts-plan.csv`. Klient používá stejný write-ahead ledger, hard stop a technický retry jako produkce, vlastní `generation-state.json` v ignorovaném `work/`, limit pokusů na ID, limit požadavků a kreditní strop; `--audit` páruje výstupy s history. Produkční ledger se nemění; přijatý zdroj se zapisuje až po úspěšné WEM QC.
